# Changelog

## Unreleased

- feat: faster upgrades after the first fun gate. Every dropper, upgrader and collector now has levels 1 to 10: once bought, its pad stays and sells the next level, and standing on it keeps buying while the cash lasts. The belt winds across the plot in three rows, 420 studs instead of 90, and tier 1 has 24 machines instead of 12 (new: Tin, Emerald, Ruby and Sapphire Droppers, Sorter, Smelter, Painter, Engraver, Plater and Crystallizer upgraders, Turbo Conveyor, Mega Collector). Each machine's pad sits right beside it on the belt, and a pad you cannot afford yet turns grey. The pacing target is now no wait over 40 seconds, levels included; the balance tool buys machines and levels and finds a longest wait of 22 seconds, with every machine bought in about 18 minutes. Save schema version 4 adds machine levels. Dev panel Give cash now gives $100,000 (ADR 0023).
- feat: tier 1 complete. Twelve machines (new: Iron, Silver, Gold and Diamond Droppers, Fast Conveyor, Polisher, Big Collector) on a two-row grid of pads; a better conveyor or collector replaces the old one on screen. `lune run balance` plays a fresh factory from config and joins the check, failing if a wait or the total time breaks `Economy.pacing` (all of tier 1 in about 16.5 minutes of saving, no wait over 2.5 minutes). The cash counter now ticks up smoothly between server updates, predicted from the same simulation; small gaps ease, purchases snap (ADR 0022).
- feat: the first playable factory. Step on glowing pads on your plot to buy a conveyor, a collector, a Coal Dropper, a Copper Dropper and a Washer upgrader (the first three are free); grey-box machines appear, box items ride the belt into the collector, and cash and cash per second show at the top of the screen. `FactorySim` with four kinds (dropper, conveyor, upgrader, collector), `EconomyService`, `FactoryService`, `PurchaseService`, purchase pads checked on the server for requirements, distance and price, and items drawn by each client from the same simulation. Save schema version 3 adds cash and owned machines. Dev panel buttons: Give $1,000 and Reset factory (Studio and Dev only). `validate-config` now checks machine params, requirements, names and that the factory fits on the plot (ADR 0021).
- docs: `docs/ARCHITECTURE.md`, the architecture overview: layers, start order, state owners, the network pipeline, saves, timing, config, the world, the check, and where the code differs from the plan.
- feat: the place. Six empty plots in a ring 250 studs from the origin, built by `PlotService` from `Config/Plots.luau`, each facing the middle with a spawn pad and a sign. A player gets the lowest free plot once their save loads and spawns on it from then on; it is freed when they leave. Signs show "Your factory", another player's name or "Free plot". Streaming is on, set in the Rojo project; each plot streams whole and your own stays loaded. A dev panel (Studio, the experience owner and an allow-list) with a saved test counter; save schema version 2 adds it. `validate-config` now rejects overlapping plots (ADR 0020).
- feat: save system. `DataService` loads each player's save through ProfileStore 1.0.3 (vendored), migrates it on a copy to the current schema, checks it and only then lets the player in. A save from a newer build is refused untouched; a save that fails its check is kept untouched, copied to a quarantine store and the player asked to rejoin. Other services read a frozen snapshot with `get` and change data with `mutate`, which keeps a change only if the save stays valid. Session states Loading, Playing, Releasing and Ended; requests are handled only while Playing. Schema version 1 counts joins. Studio saves for real only on the Dev place with API access on (ADR 0019).
- feat: network layer. Every remote is declared in `Network/Remotes.luau` with its payload rule, rate limit and an example. `ServerNet` checks each request (shape limits, payload rule, rate limit, session) before its handler and counts strikes, kicking at 30 in a minute; `ClientNet` checks its own requests and stays under 80% of each limit. One test remote, `RequestTestPing`, answered by `TestPong`. The abuse suite is generated from the definitions and runs in the unit tests and through the real remotes at the start of every Studio playtest. New config: `Tuning.Network` and `Strings.luau` (ADR 0018).
- feat: config loader. `Config` loads `Build`, `Flags`, `Tuning` and the `Buildables` registry, checks them against `Config/Schema.luau` and deep-freezes them; a bad value stops startup with a readable message. Log levels now come from `Flags.luau` and every log line starts with the build version. New check steps: `gen-index` (registry indexes), `check-literals` (no tuning numbers in services, logic or controllers) and `validate-config` (ADR 0017).
- feat: core utilities. `Log` (tagged levelled lines), `Rng` (seeded named streams, ADR 0016), `FixedStep` and `Scheduler` (fixed 10 Hz steps, at most 5 per frame, skipped time paid by formula), with specs for frame-rate independence at 30, 60 and 144 frames per second and the catch-up cap. Both `Main` scripts now drive the Scheduler, and the server logs its session seed.
- tool: the check (`lune run check`): StyLua, Selene with the project rules, luau-lsp type analysis and Lune unit tests through the new `tools/testkit.luau`. Runs before every commit through `.githooks/pre-commit` and on every push in GitHub Actions (ADR 0015).
- docs: agent rules (`CLAUDE.md`), full README with Windows steps, decision-record template and records 0001 to 0014 for the decisions made so far.
- tool: repository scaffold (folder structure, Rojo project, pinned tools and packages, lint and format configs, Git LFS rules).
